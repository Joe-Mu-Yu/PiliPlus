# Pure Live 关注与录制中心整合设计

日期：2026-10-20  
状态：已获用户确认；执行过程依照阶段验收与平台能力审计推进。

## 目标

在 Hyper-PiliPlus 主导航中增加“关注”和“录制中心”两个入口，将用户指定的 `Joe-Mu-Yu/pure_live` 对应功能整合到当前安装包。两个页面按 PiliPlus 的导航、主题和交互约定重新设计，并以 Apple Human Interface Guidelines 的清晰层级、一致性、可理解状态反馈为设计参考；不把 iOS 专属控件机械移植到 Android。

## 当前边界

- PiliPlus 主导航由 `NavigationBarType`、`MainController` 和 `MainApp` 页面承载，包含底栏/侧栏及用户配置等路径；新增入口必须在这些路径下保持一致。
- 当前已有 Bilibili 关注直播页（`lib/pages/live_follow/`），但没有 Pure Live 式跨平台收藏与录制中心子系统。
- Pure Live 关注功能不仅是页面，还依赖平台收藏数据、房间状态查询、标签/筛选和刷新逻辑。
- Pure Live 录制中心依赖独立的录制任务、队列、流处理、后台生命周期、持久化与文件管理；不能把播放器能力等同于录制能力。
- 来源仓库与依赖许可证、版权声明及源码提供义务须在实施前逐项审查。具体适用义务需基于实际迁移代码及分发方式确认。

## 设计

### 导航

新增两个主导航目的地，使用既有导航配置、路由和选中状态机制；不得破坏既有导航项、用户排序/显隐配置、侧栏或底栏呈现。新增入口在用户已有配置中的默认位置与兼容迁移策略，实施计划阶段结合设置存储实现确定。

### 关注

建立 PiliPlus 内的统一收藏视图与平台适配边界。收藏身份至少由平台标识和平台房间/用户标识共同确定；各平台的数据字段、状态能力和错误独立处理。首批平台需在实施前以接口与登录态审计结果确定，不假定所有 Pure Live 平台均可直接复用。

该页面对应 Pure Live 的应用内房间收藏（不是自动同步各直播平台账号的“已关注主播”列表）。页面承载平台切换、在线/录播/未开播状态、收藏管理、标签/筛选、刷新和空/错误状态。用户已确认必须能在 PiliPlus 中新增跨平台房间；首选通过可识别的直播间链接解析并验证房间后加入收藏，若平台审计显示链接入口不足，再补平台搜索。现有 Bilibili 关注能力及数据须保留，不能将平台账号关注误称为 Pure Live 收藏，也不能静默覆盖旧入口。

### 录制中心

录制中心直接迁移 Pure Live 原项目中对应的任务模型、FFmpeg 引擎/调度器、输入 relay、流解析、持久化、后台服务和必要设置/文件功能；不得另写一套功能相似的引擎或任务框架。允许的改动限于 PiliPlus 包名/目录、依赖注入与全局服务接线、应用设置/存储、Android manifest/原生桥接和 UI 导航所必需的适配，并保留上游实现来源、版权与许可证。

平台顺序按用户要求为抖音优先，然后再验证 Pure Live 支持的其他平台。用户声明已取得官方授权且范围仅限直播录制；不得据此扩展到下载回放、抓取账号数据或其他内容。授权文件未由开发侧独立审阅，需按该范围实施，且不得绕过访问控制。技术可行性及文件产物仍需验证。若原项目依赖无法与 PiliPlus 兼容，应先分析最小依赖闭包并报告阻塞，不以自行重写引擎替代直接迁移。

首个里程碑限定为一个已验证平台的手动单任务录制闭环：开始、停止、状态可见、后台运行及成品文件可访问。后续才增加并发队列、重连/恢复、自动开播检测和扩展设置。

任何平台的播放地址、请求头、Cookies、协议处理及录制权限均需单独验证，不以“能播放”推断“可稳定录制”。Android 通知、后台服务限制与存储访问作为独立技术验收项。

### 视觉与交互

两页复用 PiliPlus 的主题、排版和组件基础，采用清晰的信息层级、一致的导航与操作反馈。任务状态不只依赖颜色表达；破坏性操作需有恰当确认；加载、空数据、权限不足、网络失败和录制失败均提供可理解状态。Apple HIG 是设计参考，不作为 Apple 平台合规声明。

## 分阶段交付

1. **审计**：确认源仓库/分支、功能清单、许可证与依赖、首批平台、登录态、接口和 Android 后台/存储可行性。
2. **导航与关注**：新增导航入口，设计并接入跨平台收藏能力；保留现有 Bilibili 关注及数据；首批平台完成后再扩展。
3. **录制 MVP**：新增独立录制领域与一个平台的手动单任务闭环，完成 Android 后台与文件输出验证。
4. **增强功能**：按平台验证结果增加队列、并发、断流重连、恢复、自动开播检测和设置。
5. **视觉验收与交付**：检查底栏/侧栏、主题、状态、无障碍可读性和窄屏；运行针对性测试并构建、验签 Release APK。真机长时后台行为需真实设备测试，不以模拟器短测替代。

## 验收标准

- 两个入口可通过既有导航配置机制访问，底栏与侧栏行为一致，原导航功能不回归。
- 原有 Bilibili 关注功能及数据保持可用；首批接入平台的收藏、状态、筛选和刷新行为有针对性测试。
- 录制 MVP 在目标平台可启动、停止并生成可访问文件；后台、断网、进程回收、磁盘空间不足等失败边界有记录和可理解反馈。
- 页面采用统一设计规则，状态表达不依赖颜色单一通道；加载、空态、错误态及权限态均覆盖。
- 许可证审查未解决、平台接口未验证或无法进行真实设备验证的部分，必须作为明确限制披露，不得宣称完整迁移或可靠支持。

## 未决事项

- 是否坚持使用指定的 `Joe-Mu-Yu/pure_live` 基线，或另行授权评估不同维护分支。
- 抖音授权范围由用户声明限定为直播录制；许可文件未独立审阅。登录态、流地址有效期、录制稳定性及实际文件产物仍待验证；其他平台在此后逐一验证。
- 现有 Bilibili 关注入口是并入新关注页还是保留独立入口。
- 具体许可证义务及第三方依赖兼容性审查结论。
